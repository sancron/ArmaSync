# 2026-10-25 — MIG-032R2 — Härtung der Teildateien gegen Hardlinks und Namensaustausch

- Zeitpunkt: 2026-10-25, Europe/Berlin. Claude (Eigentümer und Integrator). Basis `development` @ `c0b5eef`; Branch `claude/mig-032r2-partial-hardening`; [Task](../tasks/MIG-032R2.md); Ergänzung zu [ADR-0009](../adr/0009-resume-range.md), Abschnitt „Härtung“.
- Auslöser: Review-Befund zu MIG-032R (P1, zwei Punkte): Hardlink als `.part` kann beim Fortsetzen außerhalb des Zielordners kürzen; `.state` wurde per `fs::write` über einen Link geschrieben; Namen konnten zwischen Prüfung und Öffnen getauscht werden.

## Was geändert wurde

* `crates/armasync-adapters/src/localfs/partial.rs` (neu geschrieben, Verhalten nach außen unverändert):
  * Vorhandene Namen werden nie zum Schreiben geöffnet. Frischer Start: Eintrag entfernen, `create_new`.
  * Fortsetzen: gültige Bytes lesend aus dem alten Namen in eine neue Datei `<name>.tmp` kopieren, Quellhandle vor dem Rename schließen, dann Rename. Der Kopierpfad ist eine bewusste Kostenentscheidung gegenüber dem Schutz.
  * Zustand: Schreiben über `…state.tmp` (neu angelegt) und Rename.
  * Öffnen mit Linkschutz: Windows `FILE_FLAG_OPEN_REPARSE_POINT` und Freigabe ohne `FILE_SHARE_DELETE`; Linux/Android `O_NOFOLLOW`; macOS/iOS `O_NOFOLLOW`. Prüfung auf dem Handle (`is_plain_handle`), nicht auf dem Namen.
  * Ein Ablehnungsgrund bei der Fortsetzung führt zum frischen Start (kein Fehler für den Aufrufer).
* `crates/armasync-adapters/tests/localfs_partial_sentinel.rs` (neu, 3 Fälle): externer Sentinel, verlinkt an `.part` (Fortsetzungspfad), an `.state` (Schreibpfad) und an `.part` im frischen Pfad. Der Test prüft, dass der Sentinel unverändert bleibt. Verlinkt wird per Hardlink; ein Symlink ist nur Fallback, wurde nicht benötigt. Keiner der Fälle wurde übersprungen.
* ADR-0009 um einen Abschnitt „Härtung“ ergänzt.

## Warum der Kopierpfad

Stabiles Rust (MSRV 1.85) kann die Linkzahl unter Windows nicht lesen (`number_of_links` ist nur über `windows_by_handle` nightly verfügbar). `unsafe` ist im Workspace verboten, eine Win32-Abfrage über `windows-sys` scheidet deshalb aus. Statt eine Linkzählung zu prüfen, wird der alte Name nie beschrieben. Die gültigen Bytes werden kopiert; die Gesamtprüfung über Größe und Hash bleibt unverändert.

## Nicht geprüft / Grenzen

* Unix-Pfadrennen zwischen Prüfung und Öffnen (RB-01) bleibt offen; `O_NOFOLLOW` schließt nur den Symlink-Fall am letzten Namensteil.
* Linkzahl wird nicht geprüft (siehe oben). Ein Hardlink auf eine externe Datei wird gelesen (Kopie) und nie beschrieben.
* Kein Test mit echtem Namensaustausch während eines laufenden Prozesses (nicht deterministisch); die Abdeckung ist über die Sentinel-Fälle und die Handle-Freigabe hergestellt.
* WSL/Linux, GitHub-CI: nicht gestartet (zurückgestellt).
