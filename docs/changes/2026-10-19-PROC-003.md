# 2026-10-19 — PROC-003 — Plattformsperre ohne Umgehung im Release-Build

- Zeitpunkt: 2026-10-19, Europe/Berlin. Claude. Basis `aaaba2a`. [Task](../tasks/PROC-003.md).
- **Befund:** `--allow-unreleased-platform` (MIG-031) war eine normale `clap`-Option in allen Builds. Wer die Release-Binärdatei unter Linux benutzte, konnte `armasync sync run --allow-unreleased-platform` ausführen und damit die Sperre wegen RB-01 (Unix-Pfadrace) umgehen. Die GUI hatte keinen Override.
- **Änderung:** Die Option gibt es nur noch mit dem Cargo-Feature `unreleased-platform-override` des Pakets `armasync-cli` (nicht Standard, nicht Teil von Release-Builds; im `Cargo.toml` und in der Hilfe als reine Validierungsfunktion gekennzeichnet). Ohne Feature kennt die CLI die Option nicht; `SyncArgs` bekommt dann konstant `false`. Validierungsläufe (insbesondere die Linux-Abschlussvalidierung) bauen mit `--features unreleased-platform-override`.
- **Belege (Windows 11, lokal):** `cargo build --release -p armasync-cli`: `armasync sync run --help` erwähnt die Option nicht, `sync run … --allow-unreleased-platform` endet mit Exitcode 2 („unexpected argument“), der Text ist nicht in der Binärdatei; Debug-Build ohne Feature identisch, Debug-Build mit Feature zeigt die Option. Neue Tests `crates/armasync-cli/tests/platform_gate.rs` (laufen auf jeder Plattform): normaler Build kennt die Option weder als Argument noch in der Hilfe noch über eine Umgebungsvariable; Validierungsbuild dokumentiert sie als Validierungsfunktion; `plan` und `--dry-run` werden nie gesperrt; **auf nicht freigegebenen Plattformen verweigert ein normaler Build `sync run` mit Exitcode 8 vor jedem Netzwerkzugriff und ohne etwas anzulegen** (nur unter Linux/Unix ausführbar, siehe unten). Die Ende-zu-Ende-Tests (`sync_e2e`) sind unter Nicht-Windows nur mit dem Feature aktiv. Workflow-Tests (`platform_status_for`/`require_run_allowed`) prüfen die Entscheidungslogik für Linux, macOS und FreeBSD auch unter Windows.
- **Nicht ausgeführt:** der Test „normaler Build verweigert `sync run` auf Nicht-Windows“ (`cfg(not(windows))`) wurde **nicht** ausgeführt, weil Linux-Läufe bis zur Abschlussvalidierung zurückgestellt sind; unter Windows ist nur die Entscheidungslogik und das Fehlen der Option belegt. Keine Linux-Sicherheitsaussage: RB-01 ist nicht behoben, RB-03 nicht abgeschlossen.
