- Fehler während der Arbeit, ehrlich benannt:
  1. Die Methoden `PROPFIND` und `MKCOL` schlugen im PowerShell-Prüfskript mit `Invoke-WebRequest` ohne Antwort fehl. `curl.exe` und die CLI (reqwest) erhielten die richtigen Antworten. Die Ursache im PowerShell-Client wurde nicht untersucht; die Prüfung nutzt deshalb `curl.exe`.
  2. Eine Hilfsfunktion im Prüfskript verlor die URL. Das war ein Fehler im Skript, nicht im Server. Ersetzt durch eine einfache Schleife; der Lauf ist wiederholt.
  3. `PUT /a/%2e%2e/b.txt` ergab 201: `curl.exe` löst `%2e%2e` vor dem Senden auf und schickt `/dav/b.txt`. Die Ablehnung von `..` belegen die Rohsocket-Tests (400), nicht dieser Lauf.
  4. Der Server verwendete `println!`, das bei geschlossener Ausgabe-Pipe abbricht. Auf eine tolerante Ausgabe umgestellt.
  5. Clippy meldete zwei identische Zweige; zusammengeführt.
