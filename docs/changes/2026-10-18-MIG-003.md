## Ergebnis

`docs/migration/TRANSPORT_MATRIX.md` dokumentiert belegte Legacy-Implementierungen, Tests und Lücken für HTTP(S), Range/Resume, Proxy, FTP/FTPS, SFTP, WebDAV, Auth, TLS, zsync, Abbruch, Parallelität und Limits. Die Matrix trennt Quellcodebelege von Integrationstests und von noch offenen Aussagen.

`migration-tools/transport-testserver/` enthält einen Standardbibliothek-only Python-3-Server, Startskripte für Windows und Linux, synthetische HTTP/Auth-Daten und eine begrenzte WebDAV-Implementierung. Der Server verweigert Nicht-Loopback-Bind-Adressen, hält alle Inhalte im Arbeitsspeicher und verändert keine Dateien. Der Selbsttest deckt Range (206/416), Auth, WebDAV-Operationen und Traversal-Abwehr ab.

## Grenzen

Der Harness testet HTTP und einen kleinen WebDAV-Ausschnitt; er ist keine Implementierung eines FTP-, FTPS- oder SSH/SFTP-Servers und kein Beleg für die Interoperabilität mit den Java-DAOs. Die Matrix hält diese Lücken offen und schließt daher keine Plattform- oder Releasefreigabe.

## Korrektur nach Integrationsreview (Claude, Übernahme der Task-Bearbeitung)

- Befund: `_auth_ok()` prüfte den rohen `self.path` (`startswith("/auth/")`), das Routing nutzte den dekodierten Pfad. `GET /%61uth/files/sample.bin` und `GET /auth%2Ffiles/sample.bin` lieferten 200 ohne Credentials, `PUT /%61uth/files/x.bin` 201 (nur im Speicher, aber Auth-Pfad umgehbar).
- Fix in `server.py`: neue Methode `_route()` dekodiert den Pfad genau einmal, normalisiert ihn und authentifiziert auf genau dieser Darstellung; unsichere Pfade (`.`/`..`, leere innere Segmente, Backslash, NUL, kein führender `/`) → 400. Bei 400/401/413 wird die Verbindung geschlossen (ungelesener Request-Body kann nicht als nächster Request interpretiert werden). Loopback-only, keine echten Secrets unverändert.
- Regressionstests im Selbsttest (31 Checks statt 11, Zähler im Code): kodierte GET-Pfade (`/%61uth/…`, `/auth%2F…`, `/%61%75th/…`) ohne Auth → 401, mit Auth → 200; `/auth%2f..%2f…` und `/auth//…` → 400; kodierte PUT/DELETE/MKCOL/PROPFIND ohne Auth → 401, danach Datei weder angelegt noch verändert (`/files/evil.bin` 404, `sample.bin` unverändert, `newdir` 404); kodierter PUT mit korrektem synthetischem Zugang → 201 und lesbar.
- Negativkontrolle: mit dem alten Routing (Auth auf Rohpfad) bricht der neue Selbsttest bei `/%61uth/files/sample.bin` ab.
- Ausgeführt: Windows 11, `py -3 -B …/server.py --self-test` (Python 3.15.0): 31 Checks, Exit 0. WSL2 Ubuntu, Python 3.12.3, `python3 -B …/server.py --self-test`: 31 Checks, Exit 0; `sh -n run.sh` OK. Start über `run.ps1 18765` (Windows) und `run.sh 18766` (WSL): `/health` 200, kodierter unauthentifizierter Zugriff 401; Prozesse danach beendet.
